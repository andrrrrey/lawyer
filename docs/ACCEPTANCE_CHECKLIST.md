# Чек-лист приёмки (программа и методика испытаний)

Соответствует разделу 11 ТЗ. Проверка проводится на развёрнутой системе.
«mock» — можно проверить на демо-данных; «real» — требует подключённых доступов.

## Инфраструктура и доступ
- [ ] `docker compose -f docker-compose.prod.yml up -d` поднимает все сервисы (mock)
- [ ] Сайт открывается по **https://lawyer.futuguru.com** с валидным TLS-сертификатом
- [ ] HTTP редиректит на HTTPS; TLS 1.2+ (real/mock)
- [ ] Вход по логину/паролю; без входа API возвращает 401 (mock)
- [ ] Миграции БД применяются автоматически при старте (mock)

## Мониторинг Битрикс24 и регламент (раздел 3.1)
- [ ] Отображаются нарушения: просрочка первого контакта, зависшие, без повторного
      касания, без задачи, незаполненные поля, дубли (mock)
- [ ] Оценочные нарушения (спам/отказ «для чистоты») вынесены на решение руководителя (mock)
- [ ] Кнопка «Поставить задачу» создаёт задачу и снимает нарушение «без задачи» (mock)
- [ ] Приём вебхука Битрикс24 с проверкой токена (real)

## Админ-панель (раздел 3.2)
- [ ] Изменение порога меняет расчёт нарушений без участия разработчика (mock)
- [ ] Все параметры редактируются: пороги, задачи, поля, график/календарь, дубли (mock)
- [ ] История изменений с откатом работает (mock)

## Дашборд (раздел 3.3)
- [ ] KPI, блок «Что требует внимания», воронка, источники, выручка/маржа, ROMI (mock)
- [ ] Таблицы менеджеров и лидов; фильтры по периоду/каналу/менеджеру/источнику (mock)
- [ ] Drill-down: KPI/плитки → мониторинг/аналитика, менеджер/риск → фильтр лидов (mock)

## Сквозная аналитика и ROMI (разделы 3.4, 3.5, 4)
- [ ] Цепочка «реклама → визит → сделка → оплата → маржа» с конверсиями (mock)
- [ ] Сводка по каналам/кампаниям с проваливанием до сделок (mock)
- [ ] ROMI по каналам/кампаниям; приведение НДС Директа к единой базе (real)
- [ ] Рекомендации по бюджету; список минус-слов с выгрузкой в формате Директа (mock)
- [ ] Данные связываются из Директа, Метрики, Calltouch, Битрикс24, МойСклад (real)

## AI-слой (раздел 3.6)
- [ ] AI-инсайты отображаются; вызовы модели — по расписанию, не на каждое событие (mock)
- [ ] Расчёт метрик/контроль сроков/атрибуция — детерминированы, без LLM (mock)
